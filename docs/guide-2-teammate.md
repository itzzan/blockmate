# 自托管 AI 伙伴 · 第二阶段手册：从"听指挥的帮手"到"会独立干活的队友"

草稿 · 2026-10-23 · 接《小白版从 0 到 1 实施手册》（docs/guide.md）之后

第一本手册做完的伙伴是一个**听指挥的帮手**：你说一句，它做一个动作（跟随、停、过来、捡起、交付），做完回一句。这本手册把它带到下一个台阶：**会独立干活的队友**。做完的标志是一句话——你说"去弄 20 根木头回来"，它自己找树、砍够、走回来、交到你手上，中间卡住了会回来问你，而不是傻站着或者乱来。

远处的目标（能带你通关、换整合包还能玩）不在这本里，但这本里的每一个决定都为那个目标留了路，见"读之前"的最后一条。

## 读之前：这一阶段在做什么、不做什么

**一句话说清**。要让它独立干活，缺三样东西：**更多动作**（现在它不会砍、不会挖、不会合成、不会吃、不会睡）；**把一句话拆成多步的能力**（现在一句话只能变成一个动作）；**几条铁的安全规矩**（动作多了，拆错你的房子、丢光你的东西的风险才真正出现）。这三样分别落在三层里，这三层从现在开始就要分开放，以后换整合包只换其中一层：

| 层 | 管什么 | 放在哪 | 例子 |
| --- | --- | --- | --- |
| 执行 | 一个动作怎么在游戏里做出来 | 模组 `mod/`（executor） | "砍树"= 用 Baritone 的挖掘过程挖指定方块，再把掉落捡起来 |
| 决策 | 现在该做什么、按什么顺序、失败了怎么办 | 后台 `server/`（Brain + 任务队列） | "弄 20 根木头"= 找树 → 砍到 20 → 回到主人 → 交付 |
| 知识 | 游戏常识：什么能挖、什么不能碰、怎么合成 | 数据文件 `knowledge/` + 从游戏里读 | 允许挖的方块清单；配方直接问游戏客户端，不写死 |

**这次做到哪里为止**。原版生存，和平或普通难度，白天为主。动作加到十来个，能完成"采集 → 加工 → 交付"和"回家 → 睡觉"这两类多步任务。**不做**：战斗（打怪、保护主人）、建造房子、下界和末地、主动规划长期目标（"我们今天该去找钻石了"）。这些是第三阶段"向导"的内容。

**三条铁规矩，整本手册的代码都受它约束**：

1. **只碰白名单里的方块**：允许挖的方块写在 `knowledge/blocks.yaml` 里（原木、原石、几种矿、沙土），不在名单上的一律不挖；箱子、熔炉、门、床、任何"看起来是建筑的"永远不碰，哪怕你叫它碰。
2. **只放三种方块**：工作台、火把、它自己的床。其余不放。放了工作台用完要收回。
3. **"停"永远最高优先级**，不经过模型，收到就停，正在做的多步任务整个作废。

**为将来留的路**：三层分开放；知识尽量从游戏里读而不是写在代码里（合成就是例子：问客户端的配方表，而不是维护一份配方文件）；每个任务的目标、步骤、结果都存进记忆，第三阶段"学习"就从这些记录里长出来。

## 做完的标准（最后一步逐条验）

| 编号 | 你能做到的事 | 怎么算通过 |
| --- | --- | --- |
| A | "去弄 20 根木头回来" | 它自己找树、砍够、回来交给你；10 次至少 8 次成功，失败时能说清卡在哪一步 |
| B | "把这些铁矿烧成铁锭"（你给它铁矿和煤） | 它合成或找到熔炉、烧好、交给你 |
| C | "做一把石镐给我"（手里什么都没有） | 它砍木 → 合成木板和木棍 → 放工作台 → 挖原石 → 合成石镐 → 收回工作台 → 交给你 |
| D | 任务做到一半你说"停" | 1 秒内停下，整个任务作废，不会过一会儿又接着做 |
| E | 任务做到一半它卡住了（关进栅栏、材料不够） | 5 秒内回来说"卡在第几步、为什么"，不无限重试 |
| F | "回家睡觉" | 走回记住的床，天黑就睡；没记过家就问你 |
| G | 它饿了 | 自己吃背包里的食物，不用你说 |
| H | 任务做完的第二天 | 它能说出"昨天我们做了石镐，木头在哪砍的" |
| I | 第一本手册的 A–G | 全部仍然通过（不能把老功能做坏） |

## 第 1 步 · 先把地基再加固一点（后台 + 协议）

**这一步在做什么**。现在后台的"任务槽"只装一个动作：新命令来了旧的就被取消。多步任务需要一个**队列**：一个计划里有若干步，后台按顺序派给模组，一步完成再派下一步，中间任何一步失败就停下来问脑子"接着怎么办"。协议也要加几样东西：新的命令名、新的失败原因、"计划"本身的消息。

### 1.1 任务单 9 · 协议扩展（protocol/）

```text
任务：扩展协议（docs/handbook.md 同步改），不改已有字段的含义。
1. CommandName 新增：goto（去一个坐标或记住的地点）、mine（挖指定方块到指定数量）、collect（捡附近所有掉落物）、craft（合成）、
   place（放方块，只允许 crafting_table / torch / bed）、pickup_block（收回自己放的工作台）、eat、sleep、go_home、remember_place、use_furnace。
   每个命令的 args 写进 handbook 第 7 节的表，和现有 9 条一样有 occupiesSlot 的标注。
2. Reason 新增：not_allowed（方块不在白名单 / 不允许放）、no_materials（材料不够）、no_recipe（没有这个配方）、
   no_bed（没床或床被占）、not_night（还不能睡）、no_place_known（没记过这个地点）、plan_aborted（整个计划被停掉）。
3. 新消息类型 plan（hub → ui）：{"plan_id","goal","steps":[{"index","command","args","state"}],"current"}；
   state ∈ pending / running / done / failed / skipped。网页用它画"进度条"。
4. Snapshot 加两个字段：time_of_day（0–24000）、is_raining；背包摘要里保留每格的数量（现在只有物品 → 总数，合成要知道有没有工作台等整件物品）。
5. 示例 JSON 和测试补齐；./gradlew :protocol:publishToMavenLocal。
验收：protocol 测试全过；handbook 第 6、7、8 节更新；mod 和 server 都能编过（它们引用的旧字段不变）。
```

### 1.2 任务单 10 · 任务队列（server/hub）

```text
任务：把 TaskSlot 从"一个动作"扩成"一个计划"。
1. 新类 Plan：plan_id、goal（原话）、步骤列表（每步 = 一条 command + args + state + result）、当前步序号、来源消息 id。
   同一时刻只有一个 Plan；单个动作（现在的用法）就是只有一步的 Plan。
2. 执行：派发当前步的 command → 等 ack → 等 result。result ok → 下一步；result 失败 → 进入"失败处理"（见任务单 11）。
   每步仍受现有超时表约束，另加整个计划的总超时（默认 15 分钟）。
3. stop：收到网页的 stop 或模型的 stop 工具 → 当前步发 stop 命令、剩余步全部标 skipped、Plan 结束为 aborted，
   给网页一条 plan 消息和一条 notice。stop 期间到达的任何 result 都忽略。
4. 每步状态变化都广播 plan 消息；INFO 日志记 plan_step index=… command=… state=…，不含原话。
5. 记忆：新表 plans(id, goal, steps_json, outcome, started_ts, ended_ts, source_message_id)；结束时写入。
   Brain 的上下文多一段"最近 5 个任务及结果"（给第三阶段的"学习"留材料，现在只是让它能说出昨天做了什么）。
验收：HubIntegrationTest 用假模型和 mock-executor 跑一个三步计划：三步顺序执行、中途 stop 后剩余步 skipped、
   第二步失败时 Brain 被问到且能选择 abort。
```

### 1.3 任务单 11 · 让脑子会拆步骤（server/brain）

```text
任务：Brain 从"选一个工具"变成"也能给出一个计划"。
1. 新工具 make_plan(goal, steps[])：steps 每项是 {command, args, why}，最多 8 步；只能用 handbook 里列出的命令和参数。
   系统提示里给出"常见任务怎么拆"的三个示例（弄木头、做石镐、回家睡觉），示例放在 knowledge/plan_examples.md，不写在代码里。
2. 单步任务（"跟我来""停"）照旧直接用单个工具，不要为了多步而把简单事变复杂：规则是"一句话能用一个动作完成就不要 make_plan"。
3. 失败处理：某一步 result 失败时，hub 把"目标、已完成的步、失败的步和原因、当前快照"给 Brain，Brain 只能从四个选项里选：
   retry（同一步再试一次，整个计划最多 2 次）、skip（跳过这步继续）、replan（给一个新的剩余步骤列表）、abort（放弃并告诉主人原因）。
   选什么都要先对主人说一句话（"木头不够了，我再去砍点"）。
4. 计划开始前先对主人说一句它打算怎么做（一句话，不要念步骤清单）；每完成一步不说话，除非这一步有值得说的结果；全部完成说一句。
5. 模型请求的快照句挪到 user 消息末尾（前缀缓存能命中，首字更快）；验收时记首字时间对比。
验收：用假模型的单元测试覆盖四种失败处理；用真模型跑 10 次"去弄 20 根木头回来"，看它给出的计划里命令和参数都合法（不合法的要被 hub 拒掉并让它重给）。
```

**这一步算做对了**：三张任务单的测试全绿；网页能看到一个三步计划的进度在 mock-executor 上走完；"停"能把计划整个作废。

## 第 2 步 · 新动作（模组 executor）

**这一步在做什么**。给身体加会的事。每个新动作都和第一本手册的 pick_up、deliver 一样：收到 command 先 ack，做的过程中发 progress，结束发 result，失败原因用协议里的词。Baritone 已经提供了几样现成的能力，我们优先用它的，不自己写寻路：`IMineProcess`（挖指定方块）、`IGetToBlockProcess`（走到某种方块旁）、`ICustomGoalProcess`（走到坐标）、`IFollowProcess`（已在用）。合成和放置 Baritone 不管，要自己写，这是本步最难的部分。

### 2.1 任务单 12 · 知识文件和白名单（knowledge/ + mod）

```text
任务：建 knowledge/ 目录，第一份文件 blocks.yaml，并让模组在进世界时读它（通过后台 hello 时下发，模组不自己读文件）。
1. blocks.yaml 三段：mineable（允许挖：所有原木、原石、深板岩、泥土、沙、砂砾、煤矿、铁矿、铜矿及其深板岩变种）、
   never_touch（箱子、熔炉、所有门和活板门、床、告示牌、栅栏、玻璃、所有"建筑类"方块；这段只是说明，规则是"不在 mineable 里就不挖"）、
   placeable（crafting_table、torch、各色床）。
2. 模组里所有会破坏或放置方块的代码只有一个入口 Rules.canMine(block) / Rules.canPlace(item)，Baritone 的 allowBreak / allowPlace
   只在执行需要它的那一步时临时打开，结束（成功、失败、被停）立刻关回去，并把开关状态打进 latest.log。
3. Baritone 的挖掘过程要配 blockBreakAdditionalPenalty 等参数，让它不为了走捷径顺手挖墙：寻路阶段 allowBreak 保持 false，
   只在"挖目标方块"这一刻允许，用 IMineProcess 自带的目标过滤实现。
验收：单元测试覆盖白名单判断；让它在你家墙边挖原石，墙一块不少。
```

### 2.2 任务单 13 · 采集类动作（goto / mine / collect / remember_place / go_home）

```text
任务：
1. goto(x,y,z) 或 goto(place)：走到坐标 2 格内 → ok；place 是记住的地点名，没记过 → no_place_known。复用 come_here 的卡住检测。
2. mine(block, count, radius=32)：用 IMineProcess 挖白名单内的方块，每挖到一个就把掉落捡起来（Baritone 挖完会自动捡附近的，但要用背包差异确认计数）；
   达到 count → ok（result 带实际数量）；radius 内找不到 → item_not_found；不在白名单 → not_allowed，连去都不去；
   超过时限（默认每个方块 20 秒）→ stuck 并带已挖数量。离主人超过 64 格就停下回 result too_far（新 Reason）。
3. collect(radius=8)：把半径内所有掉落物捡起来，背包满 → inventory_full 并带捡到的清单。
4. remember_place(name)：把当前位置和维度交给后台存（新表 places），"家"就是 name=home；sleep 成功时自动记 home 为床的位置。
5. go_home：goto(home)。
验收：见第 3 步场景 1–4。
```

### 2.3 任务单 14 · 加工类动作（craft / place / pickup_block / use_furnace）

```text
任务：这是最难的一张，分两次交：先 craft（2×2）+ place + pickup_block，验过再 craft（3×3）和 use_furnace。
1. craft(item, count)：配方从客户端的 RecipeManager 查（mc.level.getRecipeManager()），不要维护配方文件。
   2×2 配方直接在背包合成栏做；3×3 配方需要工作台：附近 8 格内有工作台就走过去用，没有就从背包放一个（走 place），用完收回（pickup_block）。
   材料不够 → no_materials（result 里说缺什么、缺几个）；没配方 → no_recipe。
   合成操作必须走会发包给服务器的路径（打开容器菜单后用 gameMode.handleInventoryMouseClick / handlePlaceRecipe），
   和第一本手册 deliver 的教训一样：只在本地改背包的方法全是假的。
2. place(item)：只允许 placeable 里的三类；放在脚边 1 格内的空位；放完记下坐标供 pickup_block 用；结束关 allowPlace。
3. pickup_block：挖回自己刚放的那个方块（只认记下的那个坐标），捡起掉落。
4. use_furnace(input, fuel, count)：附近 8 格有熔炉就用，没有且背包有熔炉就放（熔炉算一次性加入 placeable，用完收回）；
   放入材料和燃料，等烧完取出；每取出一个发 progress；燃料不够 → no_materials。
验收：场景 5–7。
```

### 2.4 任务单 15 · 生存类动作和被动行为（eat / sleep + 两条自动规矩）

```text
任务：
1. eat：饥饿值 ≤ 14 时吃背包里"最差的那份食物"（优先腐肉以外的、饱食度低的），吃完 → ok；没食物 → no_materials。
2. sleep：天黑（time_of_day 12542–23460）且 8 格内有床或背包里有自己的床（放下）→ 躺下；天亮自动起来 → ok；
   不是夜里 → not_night；没床 → no_bed；床被占 → no_bed。起床后自己放的床收回。
3. 两条被动行为（不用命令，模组自己做，但每次做都发 event 让后台知道）：
   a. 饥饿 ≤ 14 且当前没有任务 → 自动 eat；有任务时等任务结束再吃。
   b. 第一本手册补丁里的自动重生照旧；重生后如果记过 home，发 event 让后台决定要不要 go_home（后台默认：有主人在就 come_here，否则 go_home）。
验收：场景 8–9。
```

**这一步算做对了**：每个新动作都能在单人世界里单独触发（和第一本手册 6.5 一样，用 come_here 的开发后门发坐标），result 的原因都在协议表里，白名单测试里"挖墙"一次没发生。

## 第 3 步 · 真服务器上逐个验证

每个场景做 10 次，记成功次数和失败原因。在 Windows 上你当主人，伙伴在 mini 的服务器里。

| 场景 | 你说 / 你做 | 通过的样子 |
| --- | --- | --- |
| 1 | "去 x y z"（你给它一个 30 格外的坐标） | 走到 2 格内说"到了" |
| 2 | "挖 10 个原石" | 挖够、捡起、报数量；你家的墙一块不少 |
| 3 | "把地上的东西都捡起来"（你丢一堆） | 全捡起来，背包满时说清捡了什么 |
| 4 | "记住这里是家" → 走远 → "回家" | 回到那个点 |
| 5 | "做 4 个木板"（给它原木） | 背包里出现木板，result 带数量 |
| 6 | "做一把石镐"（给它原石和木棍，附近没工作台） | 放工作台、合成、收回工作台、交给你 |
| 7 | "把这些铁矿烧了"（给它铁矿和煤） | 烧好取出交给你 |
| 8 | 让它饿到 ≤ 14（跑步） | 自己吃 |
| 9 | 天黑说"去睡觉" | 找床或放床睡下，天亮起来 |
| 10 | "去弄 20 根木头回来"（多步） | A 标准 |
| 11 | "做一把石镐给我"（手里什么都没有，多步） | C 标准 |
| 12 | 场景 10 做到一半说"停" | 1 秒内停，计划作废 |
| 13 | 场景 10 做到一半把它关进栅栏 | 5 秒内说卡在哪一步 |
| 14 | 第一本手册 6.5 的 9 个场景 | 全部仍通过 |

记到小本子：每个场景的成功次数、每次失败的原因词、"去弄 20 根木头"从说话到交付的总时间、多步任务里模型被问"失败怎么办"的次数和它的选择。

## 第 4 步 · 收尾

1. 网页：计划进度条（plan 消息）、每步的状态；"停"按钮照旧。
2. 日志和记忆：plans 表有记录；第二天问它"昨天做了什么"能说出来（H 标准）。
3. 把第一本手册 7.3 的 A–G 再跑一遍（I 标准）。
4. 更新 handbook 第 7、8 节和 knowledge/ 的说明；小本子记基线：多步任务平均耗时、首字时间（任务单 11 第 5 条前后对比）。

## 出问题时查这里

| 现象 | 先看 | 常见原因 |
| --- | --- | --- |
| 它挖了不该挖的 | 模组 latest.log 里 allowBreak 的开关记录 | 某一步结束没关回去；或 Baritone 寻路时 allowBreak 没保持 false |
| 合成后背包没变 | 是不是用了只改本地的方法 | 必须走发包给服务器的路径（任务单 14 第 1 条） |
| 计划卡在某一步不动也不报错 | hub 日志 plan_step 的 state | 这一步的超时没进超时表；或模组 ack 了但没发 result |
| 它一直问"失败怎么办" | plans 表里同一目标的 retry 次数 | retry 上限没生效；或模型总选 retry，提示里要写明"同一原因失败两次必须 abort" |
| "停"之后又动了 | plan 消息里剩余步是不是都 skipped | stop 后到达的 result 没被忽略，触发了下一步 |

## 术语

- **计划（Plan）**：后台里一个目标拆成的有序步骤，每步是一条已有的命令。
- **白名单**：`knowledge/blocks.yaml` 里允许挖的方块；不在名单上的一律不碰。
- **被动行为**：不用你说、模组自己做的事（吃、重生），但每次都告诉后台。
- **知识层**：游戏常识放的地方；现在是一个目录几份文件，第四阶段换整合包时换的就是它。
