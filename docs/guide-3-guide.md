# 自托管 AI 伙伴 · 第三阶段手册：从"队友"到"能带你通关的向导"

细化版 · 2026-10-26 · 接第二阶段（docs/guide-2-teammate.md）之后 · 2026-10-23 的粗稿已并入

第二阶段做完的伙伴是**队友**：你给目标，它自己拆步骤、干活、卡住了回来问。这本手册让它变成**向导**：它知道"通关"是一条什么路、我们现在走到哪、下一步该干什么，会主动提议并带你去做，最后和你一起打掉末影龙。

这本和前两本一样按任务单做，每张开头一句"做完后你能……"（人话，你只看这句决定做不做），验收都是你在游戏里玩一遍。战斗、下界、末地没有现成的轮子，所以每一级都先做"只自保、只提议"的保守版，再放开；凡是标【待定】的，做到那一步前我再单独补一张细则给你审。

## 读之前：向导和队友差在哪

队友被动等目标；向导自己有目标。要做到这一点，缺四样东西：

| 缺的东西 | 是什么 | 放在哪一层 |
| --- | --- | --- |
| 通关地图 | "原版从空手到打龙要经过哪些阶段、每个阶段的目标是什么、需要什么" | 知识层：`knowledge/progression.yaml` |
| 进度感 | "我们现在在哪个阶段、缺什么、上次做到哪" | 决策层 + 记忆：新表 progress、world_facts |
| 主动性 | 没人说话时它也会想"现在该干什么"，并且会开口 | 决策层：空闲循环 |
| 自保和战斗 | 不自保就活不到下界；要带你打龙就得会打 | 执行层：全新的一块，Baritone 不管 |

**第二阶段已经有、这一阶段直接接着用的东西**（做之前心里有数，不重做）：

- 后台的"计划"（一句话拆成几步、失败四选一、停了全作废）、计划校验、固定短语表、地点表（places：home / bed）、知识层目录 `knowledge/`（blocks.yaml / food.yaml / plan_examples.md，连上时随 hello 下发）。
- 模组的 Rules（白名单）、BreakGuard（Baritone 开关唯一入口）、放方块 / 收回方块两个子动作、走到 / 挖 / 捡 / 合成 / 熔炉 / 吃 / 睡，以及"饿了自动吃""重生后找主人或回家"两条被动行为。
- 事件通道（death / respawn / inventory_change / auto_eat / bed_collected …）：这一阶段的新事件（看见地标、打了一架、带路停下了、换了维度）走同一条通道。

**铁规矩在第二阶段的三条（只挖白名单、只放三种、"停"最高优先）之上加三条**：

4. **它提议，你决定**：任何会改变存档状态的大动作（点燃传送门、进要塞、放末影之眼、打龙）它只提议，你说"去"才动。后台用一种新的计划步骤"问主人"来实现：计划走到这一步就停下问你，你说"去 / 好"才继续，说"不 / 等会"整个计划作废。
5. **战斗只对敌对生物**：永远不攻击玩家、村民、宠物、任何和平生物；怪物也只在它或你被攻击、或你明确说"打"时才动手。敌对生物的名单放知识层 `knowledge/mobs.yaml`，代码里只有"在名单上才能打"，没有例外。
6. **离你不超过 32 格**：带路时它走在前面，但你落后超过 32 格它就停下等你；下界和末地这个数缩到 16。

## 做完的标准（最后一步逐条验）

| 编号 | 你能做到的事 | 怎么算通过 |
| --- | --- | --- |
| A | 新存档开局，你问"我们该干什么" | 它说出符合当前阶段的下一步，并解释为什么（"还没有铁，先找个洞口挖煤和铁"） |
| B | 你什么都不说，站着 | 它在 1 分钟内主动提议一件事；天黑了会提醒回家；你拒绝了它不再纠缠 |
| C | "带我去家 / 带我去村庄"（记过的地点或看见过的地标） | 它走在前面带路，你落后它就等，到了说一句 |
| D | 晚上你们在野外，僵尸来了 | 它挡在你身前打僵尸，不打村民不打你 |
| E | "我们去下界" | 它检查材料（黑曜石、打火石、食物、武器），缺什么说清，齐了带你建门，点燃前问你 |
| F | 下界里"找要塞 / 打烈焰人" | 带路、协助打烈焰人、收集烈焰棒，你落后就等 |
| G | "找末地传送门" | 你投末影之眼，它算出方向和大致位置并带路，找到要塞和传送门 |
| H | 打龙 | 它会打末影水晶（有弓）和龙（近战），会躲龙息，你死了它继续，它死了会回来；做不到的部分它说清 |
| I | 整个过程它知道进度 | 任何时候问"我们到哪了"都能准确说出阶段和缺的东西 |
| J | 第一、二阶段的标准全部仍通过 | 回归 |

## 第 1 步 · 通关地图和进度感（知识层 + 后台）

**这一步在做什么**。给脑子一张"通关路线图"和一本"走到哪了"的账。路线图是纯数据（知识层），账由后台从背包和世界事实里自动算，不靠模型猜。做完这一步游戏里看不到新动作，但你问"我们到哪了""该干什么"它答得对了。

### 1.1 任务单 16 · 通关地图（knowledge/progression.yaml）

做完后你能：问它"我们现在到哪了""接下来该干什么"，它说出"开局 / 石器 / 铁器 …"里的哪一个阶段、还缺什么、建议先做什么，和一个老玩家的判断一致。

```text
任务：写一份原版生存的阶段地图，纯数据，后台读它，不写进代码。
1. 文件 knowledge/progression.yaml，两段：
   item_groups：等价物品组，解决"石镐或更好的镐都算"——logs（8 种原木）、planks、pickaxe_stone_plus（石 / 铁 / 钻石 / 下界合金镐）、
   pickaxe_iron_plus、sword_iron_plus、bed（16 色）、cooked_food（熟肉、面包、胡萝卜…）、fuel。
   stages（有序）：start 开局 → stone 石器 → food 吃饱 → iron 铁器 → diamond 钻石 → nether_prep 下界准备 → nether 下界 →
   end_prep 末地准备 → end 末地。
2. 每个阶段：id、name（中文）、needs（目标清单：item 或 group + count）、facts（要有的世界事实，如 portal_overworld、visited_nether）、
   actions（推荐动作，用第二阶段的命令名写成计划草稿，如 "mine oak_log 8 → craft crafting_table → craft wooden_pickaxe"）、
   risks（一句提醒，如 "下界别在岩浆边挖"）、say（给主人的一句说明，如 "先砍点木头做个木镐"）。
3. 阶段完成的判定写成可机读的 done_when：needs 全部满足（只算背包里的，箱子里的不算）且 facts 全部有。
   后台从第一个阶段往后找，第一个 done_when 不满足的就是"当前阶段"，它的 needs / facts 里没满足的就是"缺什么"。
   做过的阶段记进 progress 表（见任务单 17），以后背包空了也不会退回去。
4. 后台新类 Progression（server/brain）：读文件（和 blocks.yaml 一样按修改时间热重载）、算当前阶段和缺什么、给出一句建议；
   纯逻辑，不碰模型。
验收：单元测试给三组"背包 + 事实"（开局空手、有石镐有熔炉没铁、有 10 黑曜石有打火石），算出的阶段和缺什么与你的判断一致；
     文件里 9 个阶段、每个阶段 needs / actions / say 齐全。
```

这张单里你要知道的：第 3 条"只算背包里的"是故意的——它看不见箱子，与其猜不如老实说"背包里没有"；第 4 条和前两本一样，常识进文件，代码只会读。

你怎么验：这张还看不到游戏里的变化，验收在任务单 17 一起做。

### 1.2 任务单 17 · 进度和世界事实（server/memory + brain + mod）

做完后你能：问"我们到哪了"，它一句话说清阶段和缺的东西；它路过村庄、传送门、要塞这类地标时会自己记下来，以后你问"村庄在哪"它说得出坐标。

```text
任务：
1. 新表 progress(stage, reached_ts, notes)：一个阶段的 done_when 第一次满足时写一行，以后不退回。
   新表 world_facts(id, kind, name, dim, x, y, z, ts, source)：kind ∈ village / portal_overworld / portal_nether / fortress /
   stronghold / end_portal / mine_site / danger；source ∈ owner_said / seen / task_result。
   家和床继续用 places 表（任务单 13），world_facts 只放地标，两张表都进提示。
2. 事实来源：
   a. 主人说的：固定短语"记住这里是村庄 / 矿洞"等，和"记住这里是家"一样走后台（kind 从话里认，认不出就当地点名存 places）。
   b. 它自己看见的：模组新加"地标扫描"——每 5 秒看一遍自己周围 24 格里有没有这些方块：钟（村庄）、下界传送门方块（传送门）、
      下界砖（要塞，下界里）、末地传送门框（末地传送门）、苔石砖 + 石砖楼梯一起出现（要塞）；每种 100 格内只报一次；
      发 event landmark{kind, pos, dim}。岩浆 ≥ 20 块在 8 格内时发 event danger{kind: lava, pos}（给第 2 步的带路用）。
   c. 任务结果：mine 成功的位置记 mine_site（同一地点 32 格内不重复记）。
3. 后台收到 landmark / danger 事件存进 world_facts，同一 kind 在 32 格内已有记录的不重复，网页提示一句"它看见了 xx"。
4. 系统提示加三段（都短、结构化）："现在在 xx 阶段，缺：…"（一行）；"附近的地标"（最近 10 条按距离，带方向和距离，不带原始坐标）；
   "今天做过的事"（plans 表里今天的目标和结局）。
5. "我们到哪了 / 现在到哪了 / 进度"做成固定短语，后台直接按 Progression 算出来的话回，不经过模型；
   别的问法交给模型，但给它一个工具 report_progress，返回同一段算出来的文字让它照着说，不让它自由发挥。
验收：I 标准；问 10 次"我们到哪了"和你的判断一致 10 次；走过一个村庄后网页出现"它看见了村庄"，world_facts 里有一行。
```

这张单里你要知道的：第 5 条的"不经过模型"是为了准——阶段和缺什么是算出来的事实，不该让模型编；第 2b 的地标扫描每 5 秒一次、只看 24 格，是怕像任务单 13 开挖前那样扫大范围卡住客户端。

你怎么验：开新存档或清空背包，问"我们到哪了"→ 应答"开局，缺木头"；给它一把石镐和一个熔炉再问 → "石器做完了，该吃饱 / 找铁"；带它走到村庄边 → 网页提示。

### 1.3 任务单 18 · 空闲循环和主动提议（server/brain）

做完后你能：站着不说话，一分钟内它会说"要不要去挖点铁？"这类话；天黑它提醒回家；你说"不要"它就安静；你说"好"它就开始干。

```text
任务：
1. "空闲"的定义：没有计划在跑、主人在服里（RCON 或快照看得见）、距离主人上一句话 ≥ 60 秒、距离它自己上一次主动说话 ≥ 60 秒、模型空着。
   空闲时每 60 秒跑一次"想一想"（config 里 idle.enabled / idle.interval_s，默认开、60）。
2. "想一想"是一次模型调用，输入：当前阶段和缺的东西、时间（白天 / 傍晚 / 夜里）、天气、生命和饥饿、附近地标、主人的位置和距离；
   只给三个工具：propose（say 一句 + 一个计划草稿，格式同 make_plan）、remind（kind ∈ night / hungry / low_health / danger，say 一句）、
   stay_quiet。提示里写明"大多数时候选 stay_quiet"。
3. 节流和拒绝记忆（后台，不靠模型）：
   - 提醒类同一 kind 5 分钟最多一次；
   - 建议类：主人接下来 2 分钟内说"不 / 不要 / 等会 / 别"算拒绝，同一个建议（按目标文字）10 分钟内不再提；
     连续被拒 3 次 → 进入"只在被问时说"，直到主人主动说一句话；
   - 主人刚说完话 15 秒内不主动说（避免打断）。
4. 主人接受（"好 / 去吧 / 行 / 可以"）→ 那条计划草稿走第二阶段的计划流程（校验、执行、失败四选一）；
   接受的判定和拒绝一样是固定短语，别的回答交给模型正常决策。
5. 网页：主动说的话用另一种样式（左边一个小标记"它主动说的"），和回答区分开；plans 表里由提议发起的计划 source 记 "idle"。
6. 日志：idle_tick action=propose|remind|quiet，idle_rejected goal_hash=…，idle_quiet_mode on|off。
验收：B 标准；连续观察 30 分钟，主动发言 ≤ 6 次，没有一次在你刚说完话 15 秒内或刚拒绝之后；"不要"后 10 分钟内同一建议不再出现。
```

这张单里你要知道的：每分钟多一次模型调用，MacBook 的显卡会一直有点活（好处是模型不会"冷"，坏处是你在 MacBook 上玩时可能卡一下）；不想要就把 idle.enabled 关掉，默认值你定。

你怎么验：进服站着不动 5 分钟，数它说了几次、说的对不对；说"不要"再等 10 分钟；说"好"看它动不动。

## 第 2 步 · 自保与战斗（执行层，全新）

**这一步在做什么**。Baritone 只管走路和挖，不管打架。要自己写：认威胁、靠近、挥剑、后撤、举盾、吃东西。这是整个三阶段里风险最高的一块（打错对象、追着怪跑丢、掉岩浆），所以分三级做：先"只自保"，再"保护你"，最后才"你说打才打"，每一级都有开关能关掉。

**战斗开关**：后台 config 加 `combat.mode`，取值 off / defend / protect（默认 defend），随 hello 下发给模组，网页上加一个下拉；关掉就回到第二阶段的行为（打不还手，只会跑）。

### 2.1 任务单 19 · 自保（self_defense）

做完后你能：晚上把它留在野外，僵尸来了它会打回去或跑向你；血少了会举盾、吃东西、往你或出生点跑；它不会碰村民、动物、玩家。

```text
任务：
1. 知识层 knowledge/mobs.yaml：hostile（可以打的：僵尸、骷髅、蜘蛛（夜里）、溺尸、尸壳、流浪者、女巫、史莱姆、
   烈焰人、凋灵骷髅、猪灵蛮兵、末影螨、恶魂（远程）…）、flee_only（只躲不打：苦力怕、幻翼第一版）、never（永远不碰：玩家、村民、
   所有动物、驯服过的、铁傀儡、末影人（没激怒时）、僵尸猪灵（没激怒时））。随 hello 下发；代码里只有"在 hostile 名单上才打"。
2. 模组新模块 Combat（和 Executor 并列，每 tick 跑在 Executor 之前）：
   威胁感知：8 格内 hostile 名单上的生物（按实体类型 id 匹配，不用 Monster 基类猜），记最近的一个、距离、方向；
   "被攻击"= 生命值下降且 3 格内有 hostile，或 hurt 事件的来源是 hostile。
3. 规则（写死，不经过模型；combat.mode 为 off 时整段不跑）：
   a. 被攻击或 hostile ≤ 3 格 → 面向它（lookAt）、按攻击冷却（getAttackStrengthScale ≥ 0.9 时才挥）用 gameMode.attack 打；
      手里有剑就先切到剑（快捷栏 SWAP，和放方块一样）。
   b. 生命 ≤ 8 且副手有盾 → 举盾（useItem 副手）并后退 2 格；生命 ≤ 6 → 吃东西（复用任务单 15 的吃）并向主人跑（主人不在就向出生点 / home 跑）。
   c. 远程怪（骷髅、流浪者、恶魂）：第一版直接接近；【待定】Z 字走和找掩体。
   d. flee_only 的（苦力怕）：3 格内就反方向跑 6 格再回头看。
4. 战斗期间当前任务暂停（新状态 PAUSED，不发 result，发 progress "combat"；后台的任务超时照常数）；战斗结束（8 格内没 hostile 3 秒）恢复；
   战斗超过 30 秒、或生命持续下降 → 放弃战斗，跑向主人，发 event danger{kind: overwhelmed}。
5. 每次战斗结束发 event combat{target_kind, outcome ∈ killed / fled / gave_up, ms, damage_taken}；后台存事件、网页提示一句。
6. 每一次挥击前都过一遍"目标在 hostile 名单上且不在 never 名单上"，日志记 combat target=… allowed=true/false。
验收：D 标准的前半（自己能活）；20 次夜晚野外测试（每次 3 分钟）死亡 ≤ 3 次；0 次攻击错对象（看 combat 日志的 target 种类）。
```

这张单里你要知道的：第 1 条"按实体类型 id 匹配名单"是整张的底线——用"是不是 Monster 子类"去猜一定会把某些东西算错（比如激怒前的末影人）；第 4 条暂停不发 result，是为了让后台的计划不受打扰：打完接着干。

你怎么验：傍晚带它到野外，你站远一点看它一个人打僵尸；再站到村民旁边看它碰不碰村民。

### 2.2 任务单 20 · 保护主人与协同（protect / fight）

做完后你能：跟随时怪来打你，它会挡到你和怪之间打；你说"打那个骷髅"它才主动去打，打完回来；有弓和箭时远处的目标它用弓。

```text
任务：
1. protect（combat.mode = protect 时，跟随的升级）：威胁感知以主人为中心 8 格；hostile 接近主人 → 走到主人和怪的连线中点并攻击；
   主人生命 ≤ 8 时它优先顶在前面而不是攻击。
2. 新命令 fight(kind)：主人明确说"打"时才有（"打那个僵尸 / 打烈焰人"）；只打 kind 这一种且在 hostile 名单上（不在回 not_allowed）；
   16 格内没有回 item_not_found；打完（目标死或跑出 24 格）回 ok 带 killed 数；60 秒超时。固定短语不做（要带种类，交给模型）。
3. 远程：背包有弓和箭、目标 ≥ 6 格 → 切到弓、按住使用键蓄力 ≥ 20 tick、对准目标松开（和吃东西一样设使用键）；没弓就近战。
   这是末影水晶和烈焰人需要的；【待定】弹道提前量，第一版瞄实体中心。
4. 协同规则：主人正在打的目标它不抢（目标的最近攻击者是主人就不打，除非主人生命 ≤ 8）；主人生命低它上前顶住。
5. protocol：CommandName 加 fight；Reason 复用 not_allowed / item_not_found / timeout；TaskSlot 超时 fight 60 秒；handbook §7.1 加一行。
验收：D 标准全部；F 的烈焰人部分（有弓时 3 只烈焰人 2 只以上由它击杀）。
```

你怎么验：开 protect，晚上你站着不动，怪来了看它挡不挡；白天说"打那只僵尸"（有僵尸时）看它只打那只；把弓和箭给它、远处放个靶（骷髅）看它射不射。

## 第 3 步 · 带路、下界、末地

### 3.1 任务单 21 · 带路（lead）

做完后你能：说"带我去家 / 带我去村庄 / 带我去 x y z"，它走在前面，你落后它就停下等你，路上有岩浆、悬崖、夜里有怪它会停下说一句，到了告诉你。

```text
任务：
1. 新命令 lead(place / x y z)：地点名由后台换成坐标（和 goto 一样，places 和 world_facts 都查）；它走在前面，Baritone 目标是终点，
   每走 8 格看一次主人距离：主人 > 32 格（下界 / 末地 16）→ 停下、面向主人、发 progress "waiting"；主人进到 16 格内再走。
   不超时（像 follow），主人说"停"或"等在这"照旧最高优先。
2. 路上的危险：岩浆在前方 4 格内、前方落差 > 4 格、夜里 8 格内有 hostile → 停下发 event lead_paused{reason}，后台转成一句话给主人；
   主人说"继续 / 走吧"（固定短语）才接着走，否则 2 分钟后按 stuck 结束。
3. 到达（2 格内）发 ok；终点是地标（world_facts 里的）时说一句"到村庄了"。
4. 固定短语："带我回家"→ lead home；"带我去 xx"交给模型（要认地点名）。
5. protocol：CommandName 加 lead；Reason 复用 no_place_known / stuck / target_lost（主人离开服务器）。
验收：C 标准：三种目的地（家、看见过的村庄、一个坐标）各 5 次，都到了；你故意落后 40 格，它都停下等。
```

这张单里你要知道的：带路和跟随是反的——跟随是它追你，带路是它在前面、你追它，所以"你落后了"由它来等，不是它回头接你（第一版）。

### 3.2 任务单 22 · 下界（nether）

做完后你能：说"我们去下界"，它清点黑曜石、打火石、食物、武器，缺什么说清；齐了它按图纸把门框搭好，问你"点吗"，你说"点"它才点；进去后它跟着你走、你落后就等，找到要塞告诉你，你说"打烈焰人"它帮你打、捡烈焰棒。

```text
任务：
1. 建门：新命令 build_portal：检查黑曜石 ≥ 10、打火石 ≥ 1（缺回 no_materials 带缺的）；图纸放 knowledge/blueprints/nether_portal.yaml
   （相对坐标，4×5 门框 10 块，不要角）；在脚边 3 格内找一块平地（5 宽 5 高的空间），按图纸逐块放（复用放方块子动作，黑曜石这一次临时允许放），
   放完检查 10 块都在；这是第一次"按图纸放方块"，仅限这一张图纸。
2. 点燃：计划里建门之后是"问主人"步（铁规矩 4）：后台停下问"门搭好了，点吗？"，你说"点 / 去 / 好"才下 light_portal 命令
   （切到打火石，对门框内侧一块的内面使用），说"不"整个计划作废（门留着）。
3. 两边传送门坐标进 world_facts（portal_overworld / portal_nether）；换维度时模组发 event dim_change{from, to}，后台提示一句。
4. 下界里：Baritone 的参数【待定】（岩浆它本来当障碍，但要把 allowParkour 继续关着、把掉落容忍调小）；带路和跟随都用 16 格。
5. 找要塞：新命令 explore（Baritone 的探索过程）+ 任务单 17 的地标事件（下界砖）；看见就记 fortress 并说一句。
6. 烈焰棒：fight(blaze)（任务单 20）+ collect；珍珠：第一版不杀末影人（在 never 名单上），提示主人"珍珠得你来，或者去和猪灵换"。
7. protocol：CommandName 加 build_portal / light_portal / explore；新的计划步骤类型 ask_owner（hub 自己处理，不下发）；
   Reason 复用 no_materials / stuck / not_allowed。
验收：E、F：从主世界出发到拿到 7 根烈焰棒，全程它提议、你决定，没有一次要你教它下一步；门框一次搭对；点燃前一定问过你。
```

这张单里你要知道的：第 1 条"黑曜石临时允许放"和熔炉一样是动作内部的例外，不进 blocks.yaml 的 placeable；第 6 条珍珠不杀末影人是铁规矩 5 的直接结果，以后要改先改名单。

### 3.3 任务单 23 · 末地（end）

做完后你能：说"找末地传送门"，你投末影之眼，它看眼飞的方向算出大致位置并带路，投两次后给出坐标；找到要塞后它带你到传送门房，眼由你放；打龙时它打水晶（有弓）和龙（近战）、躲龙息、血少先撤，它死了会自己回来；做不到的它会说清只当辅助。

```text
任务：
1. 末影之眼：你投，它看——模组监听眼的实体出现和前 10 tick 的位移，算出水平方向角和"眼是上升还是下落"（下落 = 要塞就在附近）；
   发 event eye{yaw, pitch, pos}；后台把两次投掷（相隔 ≥ 100 格）的方向线求交点，给出坐标并记 stronghold 事实；然后 lead 过去。
2. 要塞内：explore + 地标事件（末地传送门框）找传送门房；补眼由主人放（铁规矩 4）；进门是"问主人"步。
3. 打龙（【待定】开工前单独写细则给你审，含"做不到就只当辅助"的退路）：
   a. 水晶：有弓用弓（任务单 20 的远程），没弓就不碰水晶、只守着你；
   b. 龙俯冲到 6 格内时近战；龙息（区域效果云实体）范围内不停留，立刻走开 4 格；
   c. 生命 ≤ 8 → 撤到最近的黑曜石柱背面吃东西，恢复后再上；
   d. 你死了它继续，但 60 秒内没造成伤害就只守传送门等你回来。
4. 它死了：末地重生在床或出生点，按 world_facts 里的传送门自己走回来（主世界传送门 → 下界 → 要塞 → 末地传送门，每段都是 lead/goto）；
   走不回来就说一句"我在 xx，过不去了"。
5. 战斗数据：每次打龙记 dragon_fight{ms, crystals_broken, deaths}（事件），小本子记用时。
验收：H：龙死；或者它清楚说明了自己做不到哪一步（比如没弓打不了水晶），而且这一句在打之前就说了。
```

## 出问题时查这里

| 现象 | 先看 | 常见原因 |
| --- | --- | --- |
| 它太啰嗦 | 日志 idle_tick / idle_rejected | 60 秒间隔或拒绝记忆没生效；"刚说完话 15 秒"没算上 |
| 它追着怪跑没了 | combat 事件的 ms 和 outcome | 30 秒放弃没生效；或"跑向主人"目标用错 |
| 它打了村民 / 动物 | combat 日志的 target 和 allowed | 名单匹配写成了"不是 Monster 就不打"之类的反向判断；必须是"在 hostile 名单上才打" |
| 阶段算错 | progression.yaml 的 done_when 和 item_groups | 漏了等价物品（石镐 vs 铁镐）；或 facts 没写进 world_facts |
| 门搭歪 / 点不着 | 图纸的相对坐标、latest.log 里 place op 的位置 | 平地没找够 5×5；点燃的那一面不是门框内侧 |
| 带路时它自己跑远了 | progress "waiting" 有没有发 | 距离检查的间隔不是 8 格；下界没用 16 |
| 眼的方向算错 | event eye 的 yaw 和两次投掷的间距 | 两次投掷太近（< 100 格）交点误差大；或取了落地后的位移 |

## 术语

- **阶段（stage）**：通关地图里的一格，从开局到末地共 9 个；"当前阶段"是第一个没做完的。
- **世界事实（world_facts）**：它知道的地标和危险，带坐标；和地点表（places：家、床）分开存。
- **空闲循环**：没人说话时后台每分钟让它想一次"要不要说点什么"，大多数时候的答案应该是"不说"。
- **问主人（ask_owner）**：计划里的一种步骤，走到就停下问你，你说"去"才继续。
- **combat.mode**：off 不打；defend 只自保；protect 自保 + 保护你。"你说打才打"（fight）在 defend 和 protect 下都可用。
